# 時事多渠道撰稿提示詞

用途：讓 AI 根據本知識庫，結合時事，一次寫出官網、Facebook 及 LINE 三篇推廣稿。本檔是提示詞範本，不是來源，也不核准任何產品說法。寫作規則以 [AGENTS.md](../AGENTS.md)、[Schema](../schema/SCHEMA.md) 及 [品牌觀察](../wiki/writing/brand-observations.md) 為準。

## 使用方式

1. 開一個新的對話，讓 AI 先讀 AGENTS.md。
2. 替換提示詞中 `【 】` 標示的欄位。時事要提供新聞網址與重點，AI 只依你提供的資料引用時事。
3. 產出的文章存在 `drafts/`，狀態為待審。發布前要逐項核對查核表中的［待確認］事項。

## 提示詞

```
你是 UGUARD 行銷團隊的資深撰稿人。請以 Mkt_KG 知識庫為唯一的產品依據撰寫文章：先讀 AGENTS.md、index.md 與 wiki/writing/brand-observations.md，再查相關的產品頁、claims 與 issues。

【主打產品】
DefenseTrust（可替換）

【當前時事熱點】
【貼上新聞標題、重點與網址，例如：iThome 資安週報 2026-10-23，https://www.ithome.com.tw/news/179896】
時事內容只能根據我提供的資料，不要自行補充或編造新聞細節。

【任務目標】
結合時事與知識庫中的產品定位，寫出 3 篇針對不同渠道的文章：

1. 官網文章（主打：時事解析＋專業信任感）
- 讀者：企業 IT 主管與資安負責人。
- 結構：標題 → 時事導言 → 企業面臨的風險 → 產品如何協助 → 下一步 CTA。
- 格式：一個主標題、2～3 個小標題，產品亮點用條列。800～1,200 字。最後附一段 120 字以內的 SEO 摘要。

2. Facebook 深度共鳴文（主打：痛點情境＋解決方案）
- 從時事帶來的日常工作痛點切入，引起 IT 人員共鳴，再自然帶出產品如何協助降低風險。
- 格式：一個標題，產品亮點用條列（引用知識庫的核准說法），可適度使用 Emoji。400～600 字，結尾加 Hashtag。

3. LINE 官方帳號導購文（主打：痛點情境＋活動）
- 讀者是既有好友與老客戶。內容簡明扼要，強調現行活動與截止日期。
- 格式：一句吸引人的前導句、核心活動資訊、清楚的［按鈕標籤：連結］。200 字以內。

【撰寫規則】
- 產品效能、數字、活動與期限，只能使用知識庫中狀態為 approved_current 的說法。
- 引用 source_reported 的內容時，要標示為「待產品確認」。
- 不使用「零誤判」「零時差」「完美解決」「徹底防堵」「業界最快」等絕對化說法。
- 時事只能作為切入點，不能暗示產品可以阻擋該起攻擊。
- 沒有核准的連結、電話或活動條件，一律寫成［待確認］，不要自行編造。
- 不要拿與 UGUARD 自家產品漏洞相關的事件作為推廣題材。

【輸出要求】
1. 依序直接輸出 3 篇文章，不加開場白或結語。
2. 文章之後附一張「查核表」，每列包含：說法｜知識庫依據｜狀態｜發布前待確認事項。
3. 將 3 篇文章存成 drafts/ 下的一個檔案，狀態為 draft；不需要提交，也不得對外發布。
```

## 注意事項

- 「不需要提交」是為了現場展示時節省時間。正式使用時可以刪掉這一句，讓 AI 依 AGENTS.md 執行 lint 後再提交。
- LINE 文可用的活動要以知識庫的核准狀態為準。2026-11-01 時有效的是[老客戶免費健檢](../wiki/events/health-check-campaign.md)（至 2026-12-31）與汰舊換新方案（至 2027-12-25）；健檢報名連結尚未確認。
- 範例成果見 [DefenseTrust 10 月官網文草稿](../drafts/2026-11-01-defensetrust-october-001.md)。
